## Notes for next session
- **`pgx.BeginFunc` rolls back on ANY non-nil return — including a deliberate business-logic sentinel, not just a real DB error (1.2, found by testing).** `VerifyEmail`'s "wrong code" path called `IncrementVerificationTokenAttempts` then returned `ErrInvalidOrExpiredCode` directly from the closure — the increment got silently rolled back every time along with the "error," so attempts never actually accumulated and the 5-attempts lockout never engaged. Fixed by deciding the business outcome (`invalid bool`) inside the transaction but only returning the sentinel error *after* `pgx.BeginFunc` returns (committing first). Check any other `pgx.BeginFunc`/`WithTenantTx` closure that returns a non-DB sentinel error while *also* wanting an earlier write in the same closure to stick — the write won't.
- **`ChiServerOptions.Middlewares` (oapi-codegen's chi-server) wraps iteratively, so the LAST entry is outermost and runs FIRST** (1.2, found by testing) — `[]MiddlewareFunc{A, B}` means B wraps A wraps the handler, so B runs before A. `identity/api/routes.go` needs `withAnonymousTenant` *last* in the slice so it sets the tenant context before `idempotency.Middleware` (which comes first in the slice, so it's innermost) looks for one. Got this backwards on the first attempt — every request failed with "no tenant in request context." This only matters for oapi-codegen's generated `Middlewares` field; `chi.Router.Use()` itself applies in the order called, not reversed.
- **`Makefile`'s `gen` target glob (`docs/api/*.yaml`) also matched the `*.oapi-codegen.yaml` config files themselves** (1.2, found by testing) — once a real `docs/api/identity.yaml.oapi-codegen.yaml` existed, `make gen` tried to treat the config file as a spec and look for `identity.yaml.oapi-codegen.yaml.oapi-codegen.yaml`. Fixed with a `case` skip in the loop. Not caught earlier because no OpenAPI spec existed until this task.
- **Email normalization's fuzz test found two real idempotence bugs in `net/mail.ParseAddress` round-tripping** (1.2) — a quoted local part containing a space (`" "@0`) loses its quoting through `mail.Address.Address`, and the unquoted result sometimes parses differently a second time (RFC 5322 folding-whitespace tolerance differs between quoted and unquoted parsing paths in the stdlib). Fixed by validating the local part against a strict dot-atom allow-list regex after parsing, rejecting anything that needed quoting in the first place, rather than chasing every stdlib round-trip mismatch. Regression corpus committed under `internal/identity/domain/testdata/fuzz/`.
- **`citext` needs `public` in `search_path`, found the hard way (1.1):** `CREATE EXTENSION citext` installs its operators wherever the migration connection's default schema was (`public`, for a fresh superuser session) — regardless of which schema the `citext` *column* itself lives in. A connection with `search_path=identity` (no `public`) doesn't error on `email = $1`; it just silently stops being case-insensitive, comparing as plain text instead. Any schema using `citext` (identity's `users.email` and `sso_connections.domain`; `accounts.tenants.billing_email` per data model §4) needs `public` in its `search_path` alongside its own schema, not just its own schema.
- **goose-formatted migration files work as `sqlc`'s schema input directly** (1.1): `sqlc.yaml`'s `schema: migrations/identity` pointed straight at a file with `-- +goose Up`/`-- +goose Down` sections in it, and `sqlc generate` correctly built its catalog from the Up section only, ignoring the Down section's drops — confirmed by checking the generated models actually included every table, not an empty catalog from processing the drops too. No separate "schema-only" file needed.
